# What BOD 26-04 says, and how this project relates to it

Read on **2026-11-11** from the pages below. This is a summary of the directive for context, not a substitute for it; the directive is the authority.

Sources:

- [BOD 26-04: Prioritizing Security Updates Based on Risk](https://www.cisa.gov/news-events/directives/bod-26-04-prioritizing-security-updates-based-risk) (CISA web version, dated Jun 10, 2026), cited below as **[D]**.
- [BOD 26-04: Implementation Guidance](https://www.cisa.gov/news-events/directives/bod-26-04-implementation-guidance-prioritizing-security-updates-based-risk) (dated Jun 10, 2026, page shows "Updated: August 25, 2026"), cited as **[IG]**.

## Verified

**Who it binds.** Federal Civilian Executive Branch agencies. It does not apply to contractors unless the contract says so [D, Scope]. It revokes BOD 19-02 and BOD 22-01 [D, Background]. A private-sector tool is therefore not "compliant" or "non-compliant" with it; at most it can be informed by it.

**Four variables set the remediation deadline** [D, Background]:

1. **Asset Exposure** (Publicly Exposed): is the asset accessible to unauthenticated or untrusted entities over public networks such as the internet. Per [D, Appendix A], if any method finds the asset publicly exposed the value is Yes. Agencies supply this (CISA Cyber Hygiene scans, CDM, or scanners).
2. **KEV Status** (In the KEV): the CVE has an entry in the CISA KEV Catalog.
3. **Exploit Automation** (Automatable by Adversary): an adversary can automate all the steps needed to exploit it.
4. **Technical Impact**: partial control or total control of the asset after exploitation.

CISA publishes KEV status, Automatable and Technical Impact per CVE through the Vulnrichment Program [D, Background]; definitions follow CERTCC/SSVC [D, Appendix A].

**Table 1: Remediation Timelines** [D, Appendix A]. In the web version Table 1 is an image (alt text: "BOD 26-04: Table1-Remediation Timelines", `/sites/default/files/2026-06/BOD_26-04_Table_1_Remediation_Timelines_0.png`). | 2 | Yes | Yes | Yes | Partial | 3 days |
| 3 | Yes | Yes | No | Total | 3 days & forensic triage |
| 4 | Yes | Yes | No | Partial | 14 days |
| 5 | Yes | No | Yes | Total | 3 days |
| 6 | Yes | No | Yes | Partial | 14 days |
| 7 | Yes | No | No | Total | 14 days |
| 8 | Yes | No | No | Partial | 60 days |
| 9 | No | Yes | Yes | Total | 3 days & forensic triage |
| 10 | No | Yes | Yes | Partial | 14 days |
| 11 | No | Yes | No | Total | 14 days |
| 12 | No | Yes | No | Partial | 14 days |

Consequences visible in the table: KEV is one input of four, not the first sort key. Row 5 (not in KEV, exposed, automatable, total control) gets 3 days, while rows 4, 10, 11 and 12 (in KEV) get 14. A KEV CVE that is not exposed, not automatable and partial-control still gets 14 days (row 12), while a non-KEV CVE can wait for a system upgrade.

**Timeline mechanics** [D, Appendix A]: the clock starts at the earlier of KEV addition or the agency identifying the vulnerability on an asset (BOD 23-01 / CDM); timelines are per asset and dynamic (removing an asset from the internet changes "Publicly Exposed" and the timeline); "& forensic triage" means remediation or mitigation within three days plus a forensic triage of the asset. Phase III (remediate within Table 1) takes effect within 180 days of issuance [D, Required Actions]. [IG] gives forensic triage steps and states that its sub-timelines are recommended practice; the requirement is that an adequate triage is performed.

**The directive says Table 1 "is informed by" SSVC** [D, Appendix A], i.e. it is a decision table, not a weighted score. It does not use EPSS, CVSS or an asset-criticality rating as inputs.

## How this project relates

`kev_prioritize.py` is **not** an implementation of BOD 26-04. It is a simple weighted score of its own design (KEV 0.40, ACR 0.25, EPSS 0.20, CVSS 0.20) that sorts known-exploited vulnerabilities first, a KEV-first idea that predates and is only one input of the directive. It does not model:

- **Asset exposure** (publicly exposed yes/no) as a decision variable. The optional `internet_exposed` column is carried through but not scored.
- **Exploit automation** (Automatable) and **Technical impact** (partial or total control).
- **Per-asset deadlines** (3, 14, 60 days, fix on upgrade) or the forensic-triage flag.
- The KEV `forensicTriage` field present in the current catalog.

EPSS, CVSS and the asset criticality rating are this project's additions; none of them is an input to Table 1. A faithful implementation would be a lookup on the four variables above, not a weighted sum. That would be a separate mode and is not built here.
