## Sampling

Non-KEV CVEs are ordered by `sha256("<seed>:<CVE ID>")` and the first 5,000 are kept; seed `kev-risk-prioritization-2026-11-11`. This uses no random-number generator, so the result does not depend on the Python version. The full EPSS file also yields exact population counts of non-KEV CVEs at EPSS >= 0.1 / 0.5 / 0.9 (16,203 / 3,473 / 337 of 403,085), stored in `SNAPSHOT.json` so precision can be stated at population prevalence without shipping the full file.

## Rebuild

```bash
# fresh download (will fetch today's KEV, which will differ from the pinned one)
python scripts/fetch_snapshot.py --date 2026-11-11

# exact reproduction from raw files you saved yourself; compares and writes nothing
python scripts/fetch_snapshot.py --date 2026-11-11 --kev-file known_exploited_vulnerabilities.json \
    --epss-file epss_scores-2026-11-11.csv.gz --check
```

cisa.gov serves only the current catalog, and EPSS files are published per date, so the committed KEV JSON is the pin for KEV; its hash is checked by the test suite.

## Caveats

- **Circularity.** EPSS is trained on exploitation evidence, and FIRST lists VulnCheck KEV among its data partners (https://www.first.org/epss/how-it-works). EPSS and KEV are therefore not independent signals; do not read EPSS-vs-KEV separation as validation of either.
- **KEV is not ground truth.** Absence from the catalog does not mean a CVE is unexploited.
- **No CVSS.** Neither source carries it, and it was not fetched (NVD API limit: 5 requests per 30 seconds without a key).
- The snapshot is one point in time; it supports descriptive statistics, not forecasting claims.
